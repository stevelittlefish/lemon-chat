1 — Overview & Design Goals

lemon-chat is a self-hosted AI chat UI that connects to locally-running language models via any OpenAI-compatible HTTP API (Ollama, vLLM, llama.cpp, etc.). Every conversation is persisted in a local SQLite database. The application ships as a single Go binary that also serves the frontend's static files.

Core constraints (non-negotiable)
  • No CGo — pure Go SQLite driver (modernc.org/sqlite)
  • No JS bundler, transpiler, or build step
  • Minimal dependencies — justify every new package
  • Config in TOML only; no runtime config UI for model/server settings
  • Singular DB table names (user, not users)
Architecture principles
  • Standard library net/http with Go 1.22 method+path routing
  • Server-side sessions in SQLite (not JWTs)
  • SSE for streaming model responses
  • Custom WebSocket (RFC 6455) without external library
  • Responsive Vanilla JS with native ES module imports
  • Design system tokens defined in CSS custom properties

4 — Backend Packages

cmd/lemon-chat

main.go
Entry point. Parses flags (-config, -debug, -list-models), loads TOML config, opens SQLite store, bootstraps admin user on first run, starts background workers (title, cleanup), creates WebSocket hub, starts HTTP server.
Go

internal/config

config.go
TOML structs. Top-level fields: Debug, DefaultModel. Nested: Server (port, db_path), Bootstrap (admin credentials), ModelServers[], Models[]. ServerForModel() resolves which server hosts a given model name. Env var overrides for port, db path, admin credentials.
Go

internal/debug

debug.go
Package-level Enabled bool. debug.Log() is a no-op unless enabled. Set via -debug flag or debug = true in config.
Go

internal/tasks

titles.go
StartTitleWorker: background goroutine, polls every 30s via ListUntitledEligible (5+ min old, ≥2 messages, no title).
GenerateTitleForConversation: on-demand async title gen; truncates message history to 3000 chars; uses character's title_prompt if set; calls onTitled callback on success.
Go
cleanup.go
StartCleanupWorker: runs every minute. DeleteStaleConversations removes conversations >30 min old with fewer than 2 messages (abandoned new-chat sessions). Broadcasts conversations_changed on delete.
Go

internal/server

server.go
Router setup with Go 1.22 method /path syntax. Houses writeJSON, writeError, internalError, serveFile helpers. Static files served from http.Dir("static") wrapped in no-cache middleware.
Go
middleware.go
requireAuth: validates session cookie, loads user into request context. requireAdmin: composes on top of requireAuth, checks is_admin. noCacheMiddleware: adds Cache-Control: no-cache to all static responses. currentUser(r): extracts user from context.
Go
ws.go
Custom RFC 6455 WebSocket. Hub holds a mutex-protected map[net.Conn]struct{}. Upgrade via HTTP hijacking. sendTextFrame builds wire frame. drainFrames reads incoming frames, handles ping→pong. Broadcast methods: BroadcastTitleUpdate, BroadcastConversationListChanged.
Go
avatars.go
Receives multipart upload, sniffs content-type (512-byte prefix), validates ≤5 MB image. Processes: center-crops to square, scales to 256×256 via CatmullRom, encodes as JPEG (85% quality). Saves to {db_dir}/avatars/{prefix}.jpg, deletes old files for same entity.
Go
messages.go
handleSendMessage: resolves model/character, builds chat history, POSTs to model server, streams SSE deltas back, persists assistant message.
handleGetMessageContext: returns the exact messages array that was/would be sent to the LLM for a given message.
handleFirstMessage: seeds a new conversation with a character's first_message.
Go

internal/store

store.go
Opens DB with FK enforcement + WAL mode. Runs sequential version-gated migrations (currently v9). Each migration inserts a row into schema_version.
Go

8 — Real-time: WebSocket & SSE

SSE (Server-Sent Events) — model streaming

Used for streaming model output back to the client. Each POST /api/conversations/{id}/messages request upgrades to text/event-stream. The server reads OpenAI-compatible streaming chunks from the model server, re-emits them as SSE events.

Event payloads (all prefixed data: {json}\n\n):

  • { "name": "assistant name" } — first event, sets header display name
  • { "delta": "..." } — incremental text chunk
  • { "stats": { prompt_tokens, completion_tokens, total_time_ms } }
  • { "message_id": 123 } — ID of persisted assistant message
  • { "error": "..." } — on failure
  • [DONE] — stream termination

Client uses AbortController to cancel mid-stream (stop button).

WebSocket — server push notifications

Custom RFC 6455 implementation in ws.go. Used only for server→client push; client messages are ignored (drained). Authenticated via session cookie at upgrade time.

Message types:

  • conversation_titled — { id, title } — updates sidebar title in place
  • conversations_changed — triggers full conversation list reload (e.g. after stale cleanup)

Hub: mutex-protected map[net.Conn]struct{}. Broadcast copies connection list before writing to avoid holding lock during I/O. Failed writes remove the connection.

9 — Background Tasks

Title Worker (tasks/titles.go)
  • Polling: goroutine, ticks every 30s via time.Ticker
  • Eligibility: title IS NULL, created >5 min ago, ≥2 messages
  • Generation: sends system + last 3000 chars of history to default_model with max_tokens=20
  • Custom prompt: character's title_prompt overrides default if set
  • On-demand triggers: (1) char auto_title=true after first exchange; (2) 3rd assistant response on any untitled conv; (3) manual via POST regenerate-title
  • Broadcast: WebSocket conversation_titled event on success
  • Post-processing: strips surrounding quotes and whitespace from model output
Cleanup Worker (tasks/cleanup.go)
  • Interval: every 60 seconds
  • Target: conversations created >30 min ago with fewer than 2 messages (abandoned "new chat" sessions that were never used)
  • Action: delete matching messages first, then conversations (two-query pattern to avoid FK violation)
  • Broadcast: conversations_changed WebSocket event if anything was deleted
  • Logging: logs count of deleted conversations and messages

10 — Authentication & Security

Authentication model
  • Server-side sessions in SQLite (not JWTs)
  • 16-byte crypto-random session IDs (hex encoded)
  • 30-day session TTL enforced in SessionUserID()
  • HttpOnly SameSite=Strict session cookie
  • bcrypt password hashing (DefaultCost)
  • Password-less accounts supported (NULL hash — any input accepted)
Input handling
  • Parameterised SQL queries throughout (no string interpolation)
  • Avatar uploads: content-type sniffing + 5 MB limit + full image decode/re-encode (strips metadata)
  • HTML escaping in JS templates via escHtml() / escapeHtml()
  • JSON decode errors return 400; internal errors return generic 500 (no stack trace leak)
Access control
  • All API routes protected by requireAuth except POST /api/auth/login
  • Admin routes protected by requireAdmin (composes on requireAuth)
  • Conversation ownership enforced: all reads/writes pass user_id to store queries
  • Character visibility: private = owner/admin only; readonly = others can read; readwrite = others can edit
  • Only owner/admin can change character visibility
  • Admin cannot delete their own account
  • Private character access returns 404 (not 403) to avoid enumeration
Notable omissions (by design for local use)
  • No HTTPS enforcement (intended for localhost/LAN)
  • No CORS headers (same-origin only)
  • No CSP headers
  • No rate limiting on login endpoint
  • No request body size limits on JSON endpoints
